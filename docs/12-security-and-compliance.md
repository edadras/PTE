## ۱. مدل تهدید (Threat Model)

| # | تهدید | اثر | کنترل |
|---|-------|-----|-------|
| T1 | نشت داده بین مستاجرها | فاجعه‌بار — پایان کسب‌وکار | Global Scope + Exception در نبود Tenant + تست blocking |
| T2 | سرقت Bot Token | تصاحب کامل ربات آموزشگاه | رمزنگاری در DB + حذف از لاگ + عدم بازخوانی در UI |
| T3 | جعل Webhook تلگرام | تزریق پیام و دستور جعلی | Secret Token + `public_id` غیرقابل شمارش |
| T4 | ارتقای دسترسی (Privilege Escalation) | تصاحب آموزشگاه | Guard اعطای Permission + تفکیک `is_super_admin` |
| T5 | Prompt Injection از سمت دانشجو | افشای Prompt، دستکاری نمره | جداسازی system/user + delimiter + Schema اجباری خروجی |
| T6 | SSRF از طریق Webhook خروجی / Flow | دسترسی به شبکه داخلی | Whitelist HTTPS + رد IP خصوصی و metadata |
| T7 | آپلود فایل مخرب | XSS، اجرای کد | اعتبارسنجی MIME واقعی + بازسازی تصویر + Sanitize SVG |
| T8 | تقلب در آزمون | بی‌اعتباری نتایج | Pool تصادفی + تشخیص کپی + محدودیت تلاش + لاگ زمانی |
| T9 | تخلیه مالی از طریق AI | زیان مالی | Quota سخت + Rate Limit + هشدار ناهنجاری |
| T10 | Enumeration دانشجو/آموزشگاه | نقض حریم خصوصی | ۴۰۴ به‌جای ۴۰۳ + ULID به‌جای ID متوالی در مسیرهای عمومی |
| T11 | دسترسی مستقیم به فایل صوتی دانشجو | نقض حریم خصوصی | باکت خصوصی + pre-signed کوتاه‌مدت |
| T12 | سوءاستفاده Super Admin | نقض اعتماد | Impersonate محدود، مکتوب، با اطلاع Owner |

## ۲. رمزنگاری

### در حال ذخیره (At Rest)
| داده | روش |
|------|-----|
| Bot Token | Laravel `encrypted` cast (AES-256-GCM) |
| Webhook Secret | `encrypted` |
| کلید API آموزشگاه (BYOK) | `encrypted` |
| توکن درگاه پرداخت | `encrypted` |
| رمز عبور کاربر | bcrypt (cost 12) |
| API Key پلتفرم | SHA-256 hash (غیرقابل بازگشت) |
| Secret وبهوک خروجی | `encrypted` |
| پشتیبان دیتابیس | رمزنگاری‌شده قبل از آپلود |

### در حال انتقال (In Transit)
TLS 1.2+ اجباری همه‌جا · HSTS · گواهی معتبر برای دامنه‌های اختصاصی · اتصال DB و Redis روی شبکه خصوصی

### چرخش کلید
`APP_KEY` نمی‌تواند بدون بازرمزنگاری همه مقادیر عوض شود. فرایند مکتوب لازم است:
```
1. کلید جدید به APP_PREVIOUS_KEYS اضافه شود
2. دستور crypto:rewrap همه مقادیر encrypted را بازنویسی کند
3. کلید قدیمی حذف شود
```
این دستور باید در فاز ۰ نوشته و تست شود، نه وقتی که لازم شد.

## ۳. حفاظت از Bot Token

سه لایه:

```php
// ۱. مدل — هرگز serialize نشود
class TelegramBot extends Model
{
    protected $hidden = ['token', 'webhook_secret', 'payments_provider_token'];
    protected $casts = [
        'token' => 'encrypted',
        'webhook_secret' => 'encrypted',
    ];
}

// ۲. UI — فقط ۴ کاراکتر آخر
TextInput::make('token')
    ->password()->revealable(false)
    ->dehydrated(fn ($state) => filled($state))     // خالی = بدون تغییر
    ->placeholder("••••••{$bot->token_last4}");

// ۳. لاگ — تور ایمنی نهایی
Log::listen(function (MessageLogged $m) {
    $m->message = preg_replace(
        '/\d{8,10}:[A-Za-z0-9_-]{35}/', '[REDACTED_BOT_TOKEN]', $m->message
    );
});
```

همین الگو برای Sentry (`before_send` hook) و برای خروجی Exception هم اعمال شود.

## ۴. حریم خصوصی داده دانشجو

### داده‌های حساس
```
نام و نام خانوادگی · شماره تلفن · ایمیل · Telegram ID
فایل صوتی (بیومتریک صوتی — حساسیت بالا)
متن نوشته‌شده · نمرات · تاریخچه پیام
```

### اصول
1. **حداقل‌سازی** — فقط آنچه لازم است جمع‌آوری شود
2. **محدودیت هدف** — داده تمرین برای تبلیغات استفاده نشود
3. **نگهداری محدود** — فایل صوتی پس از N روز حذف (پیش‌فرض ۹۰، قابل تنظیم آموزشگاه)
4. **حق دسترسی** — دانشجو بتواند داده خودش را ببیند
5. **حق حذف** — درخواست حذف حساب → حذف کامل ظرف ۳۰ روز
6. **حق انتقال** — Export داده به JSON/CSV

### ارسال به AI Provider
```
✅ ارسال می‌شود: متن پاسخ، transcript، متریک صوتی، سطح دانشجو
❌ ارسال نمی‌شود: نام، تلفن، ایمیل، Telegram ID، نام آموزشگاه
```
شناسه در Prompt همیشه ناشناس‌سازی‌شده است. اگر Provider گزینه «عدم استفاده برای آموزش مدل» دارد، به‌صورت پیش‌فرض فعال باشد.

### رضایت
دانشجو در اولین `/start` باید شرایط و سیاست حریم خصوصی آموزشگاه را ببیند و تایید کند. تایید با timestamp و نسخه سند ثبت می‌شود.

## ۵. یکپارچگی آزمون

| مکانیزم | توضیح |
|---------|-------|
| Pool تصادفی | هر دانشجو زیرمجموعه متفاوتی از سوالات می‌گیرد |
| ترتیب تصادفی | ترتیب سوال و گزینه‌ها متفاوت |
| زمان‌بندی سرور | تایمر روی سرور، نه کلاینت — دستکاری ممکن نیست |
| تشخیص کپی | شباهت embedding پاسخ‌های Writing با پاسخ‌های قبلی همان سوال |
| تحلیل زمان پاسخ | پاسخ غیرممکن سریع → پرچم بازبینی |
| محدودیت تلاش | تعریف‌شده در آزمون |
| Snapshot | ساختار آزمون در لحظه شروع قفل می‌شود |
| لاگ کامل | هر پاسخ با timestamp دقیق برای بازبینی |

**آنچه نمی‌توان کنترل کرد:** در تلگرام امکان تشخیص تعویض پنجره یا کمک گرفتن وجود ندارد. این محدودیت باید به آموزشگاه شفاف اعلام شود — آزمون تلگرامی برای تمرین و سنجش پیشرفت است، نه صدور مدرک رسمی.

## ۶. اعتبارسنجی ورودی

```php
// آپلود
'logo' => ['file', 'mimes:png,jpg,svg', 'max:2048', new RealMimeType(['image/png','image/jpeg','image/svg+xml'])],

// SVG
$clean = (new SvgSanitizer)->sanitize($content);   // حذف script, on*, xlink:href خارجی

// تصویر — بازسازی کامل برای حذف payload جاسازی‌شده
Image::make($file)->encode('png')->save($path);

// custom_css (فقط Enterprise)
$css = CssSanitizer::allow(['color','background','border','font-family','padding','margin'])
                   ->deny(['url','@import','expression','behavior','javascript'])
                   ->clean($input);

// Webhook خروجی و node وبهوک Flow
$url = UrlValidator::make($input)
    ->requireHttps()
    ->denyPrivateNetworks()      // 10/8, 172.16/12, 192.168/16, 127/8, ::1, fc00::/7
    ->denyMetadataEndpoints()    // 169.254.169.254
    ->validate();
```

**نکته SSRF:** بررسی DNS باید در **زمان اتصال** انجام شود، نه فقط زمان اعتبارسنجی — وگرنه حمله DNS Rebinding ممکن است. از یک HTTP client با resolver کنترل‌شده استفاده کنید.

## ۷. Rate Limiting

```php
RateLimiter::for('telegram-webhook', fn ($r) =>
    Limit::perMinute(600)->by($r->route('botPublicId')));

RateLimiter::for('api', fn ($r) =>
    Limit::perMinute(600)->by($r->apiKey()->academy_id));

RateLimiter::for('student-api', fn ($r) =>
    Limit::perMinute(120)->by($r->user()->id));

RateLimiter::for('login', fn ($r) =>
    Limit::perMinute(5)->by($r->ip().'|'.$r->input('email')));

RateLimiter::for('ai-per-student', fn ($r) =>
    Limit::perHour(60)->by(TenantContext::id().'|'.$r->student()->id));
```

آخری مهم است: جلوگیری از اینکه یک دانشجو (یا اسکریپت) سهمیه AI کل آموزشگاه را در یک ساعت بسوزاند.

## ۸. ثبت وقایع (Audit)

### رویدادهای با ثبت اجباری
```
احراز هویت:  ورود موفق/ناموفق · تغییر رمز · فعال/غیرفعال 2FA
دسترسی:      دعوت کاربر · تغییر نقش · ساخت/تغییر نقش سفارشی
تنظیمات:     تغییر Bot Token · تغییر دامنه · تغییر Prompt/Rubric
داده:        حذف دانشجو/آزمون/سوال · Export Excel · Import گروهی
نمره:        Override نمره AI (با دلیل اجباری)
مالی:        تغییر پلن · تغییر اطلاعات پرداخت · بازپرداخت
پلتفرم:      ساخت/حذف/تعلیق آموزشگاه · Impersonate · تغییر پلن
```

### الزامات
- Actor (کاربر یا سیستم)، IP، User-Agent، زمان دقیق
- مقادیر قبل و بعد برای تغییرات
- **غیرقابل حذف توسط کاربران آموزشگاه** — حتی Owner
- نگهداری ۱۲ ماه، سپس آرشیو رمزنگاری‌شده

## ۹. پاسخ به حادثه (Incident Response)

### طبقه‌بندی
| سطح | نمونه | زمان پاسخ | اطلاع‌رسانی |
|-----|-------|-----------|-------------|
| P1 بحرانی | نشت داده، افشای توکن، قطعی کامل | فوری | همه مشتریان ظرف ۲۴ ساعت |
| P2 بالا | یک آموزشگاه از کار افتاده، خطای نمره‌دهی گسترده | ۱ ساعت | مشتری متاثر |
| P3 متوسط | کندی، خطای پراکنده | ۴ ساعت | در صورت لزوم |
| P4 پایین | مشکل UI | روز کاری بعد | — |

### فرایند P1 (نشت داده)
```
1. مهار      — غیرفعال‌سازی مسیر آسیب‌پذیر، در صورت لزوم توقف سرویس
2. سنجش      — کدام مستاجرها؟ کدام داده؟ چه بازه زمانی؟ (از لاگ‌ها)
3. اصلاح     — رفع، استقرار، تست بازگشتی
4. اطلاع     — به مشتریان متاثر با شرح دقیق و اقدامات
5. چرخش      — همه توکن‌ها و کلیدهای احتمالاً افشاشده
6. پس‌نگری   — نوشتن Postmortem بدون سرزنش + افزودن تست بازگشتی
```

**قاعده:** هر حادثه P1 یا P2 باید به یک تست خودکار جدید منجر شود. حادثه‌ای که تست تولید نکند، دوباره اتفاق می‌افتد.
